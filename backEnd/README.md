# GitMatch - Backend Architecture & Implementation Plan

**Context for AI Assistant (Claude/Others):**
You are helping to build the Spring Boot backend for **GitMatch**, a mobile app (Tinder-style interface) that helps developers discover underrated GitHub repositories and stay up to date with tech news/release notes. The user swipes right to "Like/Star/Save", left to "Ignore", and up for "More Info". 

The backend acts as the data aggregator (Harvester), AI processor (Gemini), and REST API provider for the Kotlin Multiplatform mobile app.

---

## 🛠️ Tech Stack
* **Framework:** Spring Boot (Java or Kotlin)
* **Database:** PostgreSQL (with `pgvector` extension for AI semantic matching)
* **ORM:** Spring Data JPA
* **AI Provider:** Gemini API (via HTTP/REST)
* **API Integrations:** GitHub REST API, Dev.to / RSS feeds for news.

---

```text

├── api/                  # REST Controllers (Endpoints for the Mobile App)

│   ├── SwipeController   # Handles Swipe Right/Left actions
│   └── UserController    # Auth, preferences, and profile sync
├── core/
│   ├── entity/           # JPA Entities (RepositoryItem, NewsItem, User, SwipeAction)
│   ├── repository/       # Spring Data JPA Repositories
│   └── enums/            # SwipeDirection, SourceType
├── service/              # Core Business Logic
│   ├── FeedService       # Blends Repos and News based on user prefs
│   ├── SwipeService      # Records actions, updates recommendation weights
│   └── GitHubService     # Handles actual GitHub API interactions (Starring)
├── harvester/            # The Data Aggregation Layer
│   ├── GitHubHarvester   # @Scheduled jobs to fetch trending/underrated repos

│   └── response/         # FeedCardResponse (Unified format for Repos & News)
```

## ⚙️ The "Actual Work" - Implementation Phases for AI

When instructing the AI to build this, follow these phases:

### Phase 1: Database & Entities
1. Configure `application.yml` for PostgreSQL.
2. Create the base JPA Entities (`RepositoryItem`, `NewsItem`, `User`, `SwipeAction`).
3. Set up Spring Data JPA Repositories. Include custom queries (e.g., "Find Repos not yet swiped by User X").

### Phase 2: The Harvester (Scheduled Jobs)
1. Enable `@EnableScheduling`.
2. Create `GitHubHarvester`. Write a method that runs daily/hourly to call GitHub's search API using specific queries (e.g., `stars:100..5000 pushed:>2026-01-01` to find active, underrated repos).
3. Save raw data to the database (AI processing comes next).

### Phase 3: The AI Processor (Async)
1. Set up a WebClient/RestTemplate client for the Gemini API.
2. Create the `AiProcessorService` with `@Async` methods.
3. **Crucial:** Implement the prompt logic. Send the Repo README/News article to Gemini. The prompt MUST force JSON output: `{"summary": "...", "bullets": [...], "snippet": "...", "good_first_issues": true}`.
4. Deserialize this JSON, update the corresponding `RepositoryItem` or `NewsItem`, and save it back to the DB. Ensure graceful degradation (if AI fails, keep the original description).

### Phase 4: The Discover Feed API (Hybrid Tabbed Approach)
1. Create `FeedController`.
2. Implement paging or infinite scroll logic.
3. The response must unify `RepositoryItem` and `NewsItem` into a generic `FeedCardResponse` so the mobile app can render the swiping deck easily. Inject a `type` field (`REPO` or `NEWS`).

### Phase 5: The Analytics & Swiping API
1. Create endpoints for swiping: `POST /api/v1/swipes`.
2. When a user swipes RIGHT on a Repo, optionally trigger an async call to the actual GitHub API (using the user's OAuth token) to truly Star the repository on GitHub.
3. Track swipe history to build user preference profiles.

## ⚠️ Best Practices for AI Integration
* **Asynchronous Execution:** AI generation MUST be decoupled from HTTP request threads. Use `@Async` or a message broker.
* **Structured Prompts:** Always demand JSON from Gemini.
* **Idempotency:** The Harvester should not process or summarize the same repository twice unless there is a major update.
* **Rate Limits:** Obey GitHub and Gemini API rate limits. Implement exponential backoff in the Harvester.
